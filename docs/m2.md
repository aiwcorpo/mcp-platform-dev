# M2: one domain, system mocks, four more MCP servers

The public address of the portal and the gateway is `https://localhost:18745` (`PROXY_TLS_PORT` in `.env`). The browser and MCP clients
see one origin; MCP servers are reachable only through the gateway. The same proxy also listens on http at `:18740`
(`PROXY_PORT`, same routes and rules, no redirect), but the gateway's `MCP_PUBLIC_URL`, the BFF's `PORTAL_PUBLIC_BASE_URL`
and the broker's `MCP_PORTAL_URL` are https addresses: links, `resource_metadata`, the OIDC callback and OAuth point to https.
Reason: Safari does not store `__Host-`/`Secure` cookies from `http://localhost`, so logging in to the portal over http
ended with "Session expired". A client that logs in through `:18740` (for example a script with its own cookie jar)
is redirected to https by the BFF and cannot finish the login; use `:18745` with the CA from `certs/public-ca/ca.crt`.

## Step by step for a human

All paths are relative to the repo directory (`mcp-platform-dev`). The stack is running (`make up-m2`).

1. `make trust-ca` prints two commands. Run the first one (`security add-trusted-cert ...`, login password or
   Touch ID); restart the browser.
2. In the shell that starts Claude Code: `export NODE_EXTRA_CA_CERTS="$PWD/certs/public-ca/ca.crt"`.
3. `make users` shows the passwords of `alice`, `bob`, `carol`, `mallory`.
4. Open `https://localhost:18745` (Chrome, Firefox or Safari) and log in as `alice`; the Keycloak form is at
   `https://localhost:18746`.
5. In the portal: the catalog, "Add PAT" for Jira (`alice-pat`), "Connect through OAuth" for GitLab, then the address wizard with the chosen
   systems and access. The portal shows a ready command; since M5 nothing is stored (earlier: a stored link `/v/<slug>/mcp`).
6. `claude mcp add --transport http --client-id claude-code --callback-port 33418 <name> "https://localhost:18745/mcp?systems=jira"`
   (port 33418 free); in Claude Code `/mcp`, `Authenticate`, log in as alice in the same browser.

Side effects of the tests: `make m2` (up to M4 it creates and deletes links, since M5 it checks the address wizard) stores alice's Jira PAT (and `bob-pat` as a test of a foreign PAT, then
`alice-pat` again), and connects and disconnects alice's GitLab; after a run alice's PAT stays, and the GitLab connection state depends on the last scenario step.
`make m1` stops and restarts the broker container (`docker stop/start`, scenario A15): for the duration
of the run, until the healthcheck, the broker is unavailable to everyone using the stack.

### HTTPS and CA trust

- The server certificate for `localhost` is issued by a separate CA "dev public" (`certs/public-ca/`, `make certs`), not the internal
  mTLS CA. The internal CA has no name constraints and signs component identities; adding it to the keychain
  would make them trusted for any host. The CA "dev public" has name constraints (`localhost`, `127.0.0.1`, `::1`),
  so trusting it covers nothing except the local proxy. The CA key exists only in `certs/public-ca/ca.key`
  (git-ignored, not mounted into any container); the proxy gets the leaf `tls.crt` and `tls.key`.
- A human grants the trust (the script runs nothing, it only prints commands): `make trust-ca`. The set:

  ```bash
  # from the repo directory
  security add-trusted-cert -r trustRoot -p ssl -k "$HOME/Library/Keychains/login.keychain-db" \
    certs/public-ca/ca.crt
  export NODE_EXTRA_CA_CERTS=certs/public-ca/ca.crt   # Claude Code (Node)
  ```

  The command asks for the login password or Touch ID. Safari and Chrome read the keychain; Node does not, hence
  `NODE_EXTRA_CA_CERTS` (set in the shell that starts `claude`). To undo:
  `security remove-trusted-cert <ca.crt>`. After restarting Safari/Chrome (or opening a new tab) `https://localhost:18745`
  loads without a warning.
- No HSTS: HSTS on `localhost` applies to all host ports and would force https also on the Keycloak port `:18080` (http, used by scripts).
- TLS 1.2 and 1.3, certificate valid 397 days (the Safari limit); to renew: delete `certs/proxy` and `certs/public-ca`, run `make certs`,
  then `docker compose ... restart proxy` (after the CA changes, the new `ca.crt` must be trusted again).

### Keycloak over https

Keycloak has its own https port, `https://localhost:18746` (`KEYCLOAK_TLS_PORT` in `.env`), with a certificate from `certs/keycloak`
(the same CA "dev public", so `make trust-ca` is enough). `KC_HOSTNAME=https://localhost:18746`, so the token `iss` is
`https://localhost:18746/realms/corp`, and the cookies `AUTH_SESSION_ID`, `KC_RESTART` and `KC_AUTH_SESSION_HASH` (`Secure;
SameSite=None`) come over https, which Safari stores. The http port `18080` stays for scripts (`make token`, the admin API in
`kc-sync-bff-client.sh`) and for container traffic: the JWKS and token endpoint of the gateway and broker are still
`http://keycloak:8080/...`, and `iss` is only compared, so Java containers do not need the CA in a truststore.

Option (a) was chosen over "Keycloak behind the proxy under a path prefix" (b): the proxy routes are part of the routing contract (`/`, `/api`, `/s/`,
`/mcp` since M5, `/.well-known/oauth-protected-resource*`; up to M4 also `/v/`), and Keycloak under a prefix would need a new route and a change to that set;
a separate port does not touch the contract. The exception in the network is the BFF, which up to M3 ran discovery at the `iss` address (that is what `idp-relay` was for, unneeded today).

The portal session cookies (`__Host-session`, `SameSite=Lax`) come back from Keycloak normally, because the callback is a top-level
navigation.

## Reverse proxy (`proxy/`, service `proxy`, profile `m2`)

| Path | Target | Notes |
| --- | --- | --- |
| `/` | `portal-web:8080` | static SPA server (`portal-web/nginx.conf`): fallback to `index.html`, CSP nonce from `$request_id` |
| `/api`, `/api/` | `portal-bff:8080` | BFF OIDC callback: `https://localhost:18745/api/v1/auth/callback` (registered in Keycloak together with http `:18740` and `:18090`) |
| `/s/`, `/mcp` (M5; up to M4 `/v/`), `/.well-known/oauth-protected-resource*` | `mcp-gateway:8080` (M5: `gateway-lb:8080`, `proxy/m5/`) | public listener only; `Cookie` removed, `Set-Cookie` hidden, `nosniff` and CSP `default-src 'none'; sandbox` with `always`, proxy errors as JSON |
| `/.well-known/` (the rest), `/admin/v1/` | 404 | the gateway JWKS and admin API are on a separate mTLS listener (8443), to which the proxy has neither a route nor a certificate |

Own error pages on the gateway routes (also the rejection of a non-canonical path, 431 for oversized headers, 400
for an unknown `Transfer-Encoding`) are JSON with `nosniff` and CSP; the test checks the headers, not only the status. The access log
has paths without the query (authorization codes). `;`, `%3b` and any `%` in the paths `/s/` and `/mcp` (up to M4 also `/v/`) are rejected; the `/mcp` query (the filter) passes unchanged.

Paths are forwarded unchanged, so "normalization" means rejection: encoded dots, slashes, backslashes,
`%25`, `%00`, the segments `.`/`..` and `//` in the path part give 404 (all routes). `X-Request-Id` is neither
created nor changed. `Host` and `X-Forwarded-Host` are the fixed public origin of the listener (`localhost:$PROXY_PORT` for http, `localhost:$PROXY_TLS_PORT` for https; the file is
generated when the container starts), `X-Forwarded-For/Port/Proto` are set by the proxy (`https` on the TLS listener); the client's `Forwarded`, `X-Real-IP`,
`X-Forwarded-Prefix/Ssl/Scheme`, `X-Original-URL` and `X-Rewrite-URL` are removed. The BFF trusts `X-Forwarded-*` only from
the proxy address (`bff-entrypoint.sh` replaces `proxy.internal` with a regex; after the proxy is recreated, the BFF must be restarted). Upstreams are resolved on every request: restarting the gateway
or the BFF does not require restarting the proxy. Routes and rules are in `proxy/routes.conf`, shared by both listeners.

`make proxy-test` (`scripts/proxy-test.sh`, curl): 212 checks (including the https listener with `certs/public-ca`) against stand-in upstreams in a separate Docker
network, each rule with a positive and a negative case; it does not touch the running stack.

## System mocks (`mocks/systems/`, Python, no dependencies)

`bob-pat`, `carol-pat`, `mallory-pat`); an IdP token and a foreign token give 401 (no token passthrough). Stateless.
`GET /__mock/health` is open, `GET|DELETE /__mock/journal` with Basic `admin:$MOCK_ADMIN_PASSWORD`

### GitLab as an OAuth provider

Client `mcp-broker`, secret `GITLAB_OAUTH_CLIENT_SECRET` (`.secrets/dev.env`, also in OpenBao under
`secret/mcp/oauth-clients/gitlab`, where the broker policy has read access only). Redirect URI: `${MCP_PORTAL_URL}/api/v1/oauth/callback`
(`http://localhost:18740/...`; plus `:18090` for a BFF on the host). PKCE S256 (challenge of 43 base64url characters, verifier of 43-128 characters `[A-Za-z0-9._~-]`) and `state` are required; `scope` is required
and enforced as in GitLab: `api` writes, `read_api` only GET/HEAD (a write -> 403 `insufficient_scope`), `read_user` only
`GET /api/v4/user`, a missing or unknown scope in authorize -> `invalid_scope`; reusing a code invalidates the tokens issued from it;
two client authentication methods and repeated parameters -> `invalid_request`. The broker asks for `api` (a human
decision of 2026-10-28), so writing through OAuth (`gitlab__comment_merge_request`) works; a wrong client
or `redirect_uri` does not redirect (400). A code is single-use and valid for 120 s; the access token lives
`GITLAB_MOCK_TOKEN_TTL` s (default 7200; in `.env` you can set 60 to watch a refresh and restart
`gitlab-mock`); refresh rotates (the old access and refresh tokens stop working). State is in memory: restarting the mock
invalidates all tokens.

`/oauth/authorize` without extra parameters shows an account picker (alice, bob, carol, mallory) and
"Deny". Choosing an account other than the portal user is accepted (contracts 2.2.3: no identity comparison; the portal shows "connected as <backendUser>"). Parameters appended to the address
in the browser bar (or by a script):

| Parameter | Effect |
| --- | --- |
| `mock_user=<login>` | approves without the picker |
| `mock_action=deny` | `error=access_denied` (portal: `cancelled`) |
| `mock_scenario=wrong_state` | a different `state` in the callback (broker/BFF: `flow_invalid`) |
| `mock_scenario=provider_error` | `error=server_error` instead of a code |
| `mock_scenario=token_error` | the `token` endpoint answers 500 for this code |
| `mock_scenario=refresh_revoked` | the refresh of this grant gives `invalid_grant` (connection `revoked`) |
| `mock_scenario=short_ttl` | the access token lives 30 s |

## Profile `m2` (`make images-m2`, `make up-m2`)

`make images-m2` builds from `git archive` HEAD the BFF and web images (repo `mcp-portal`) and the four additional servers
(`ONLY=web,gitlab` limits the set); the tags `m2-<sha>` go to `.env`. `make up-m2` runs `up -d --wait` for the profiles
`full` and `m2`: Compose recreates only the services whose configuration or image changed (the list comes from
`docker compose ... up -d --dry-run`), after which `make m2-sync` applies what lies outside the container definitions:
the `mcp-portal-bff` client in the running Keycloak (from `keycloak/realm-corp.json`), the Redis ACL (`redis/*.rules`) and a proxy
restart. The broker, gateway and MCP servers have healthchecks (gateway: a response from the public listener; broker and servers:
an accepted TCP connection on 8443, because Tomcat opens connectors last), so `--wait` waits for readiness.

Gateway: image `mcp-gateway:m2-d65088f`, `MCP_PUBLIC_URL=https://localhost:18745` (the proxy; `resource` in the RFC 9728 metadata
is the proxy address), four servers under `MCP_SERVER_<SYSTEM>_MCP_URL`, the admin API under the alias `mcp-gateway.internal:8443`
(the broker and gateway-admin stubs are stopped), the `mcp-portal-bff` certificate for the BFF, `MCP_ADMIN_AUTHORIZED_PARTY=mcp-portal-bff`. The gateway
port 18000 stays only for `make m1` (the mcp-e2e scenarios connect straight to `127.0.0.1:18000`); clients use the
proxy. Broker: `mcp-credential-broker:m2-bcfec7a`, the GitLab client secret is read from OpenBao (`secret/mcp/oauth-clients/gitlab`, a policy
for that path only), with no environment variable.

The BFF (since M3) runs in the `core` network with the alias `portal-bff.internal` and an OIDC configuration without discovery (`PORTAL_OIDC_AUTHORIZATION_URI` set to the public address, token, JWKS and logout through `http://keycloak:8080`); `idp-relay` and the truststore in the BFF were removed. Earlier the BFF network alias (`portal-bff.internal`)
belonged to the relay. Logout from the IdP (`end_session_endpoint`) works as Keycloak returns it.

Servers have `MCP_<SYSTEM>_ALLOW_PLAIN_HTTP=true` (mocks over http), `MCP_CONNECT_URL=https://localhost:18745/connections?system={system}`,
their own certificates and Redis users. Service desk: a service account; since M4 the server has neither `MCP_SERVICEDESK_CREDENTIAL_MODE` nor `MCP_SERVICEDESK_ALLOWED_QUEUES`, queue access is granted only by the policy bundle, and a missing grant is `not_found_or_denied`.

What this stack does not have yet: the `service-account` credential of the service desk in the broker (key: `SERVICEDESK_API_KEY`),
and the OpenSearch `token-exchange` in the broker.

## `make m2`

A demo scenario on a running `make up-m2` stack: mocks (whoami, no passthrough, REST), the OAuth flow with the mock,
the real broker (`oauth/start` -> authorize -> `oauth/complete`, wrong `state`, denial, disconnect), the Redis ACL
(`portal-bff` without FLUSHALL/KEYS/SCAN/SCRIPT/FUNCTION/MIGRATE and without `gw:*` keys, broker: a script only on its own
keys), Keycloak, the proxy, and the portal through the proxy: OIDC login of alice, `me`, the catalog, storing a Jira PAT, "Connect through
OAuth" (GitLab) with denial and disconnect, the address from the wizard (up to M4 a link created in the portal), the MCP client (`initialize`,
`tools/list`, `tools/call`) through `/mcp?systems=jira` (up to M4 `/v/<slug>/mcp`) with RFC 9728 metadata at the proxy address,
`credential_required` with a link to the portal, logout. The run uses alice and cleans up what it created (up to M4 the link, the GitLab connection); alice's Jira PAT
is stored again with the same value. Two SKIPs remain: the web interface in a browser (no browser driver)
and Claude Code (needs a human).
