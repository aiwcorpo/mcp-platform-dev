# M2: jedna domena, mocki systemów, serwery ws-04

Adres publiczny portalu i gateway'a: `http://localhost:18740` (`PROXY_PORT` w `.env`). Przeglądarka i klienci MCP
widzą jeden origin; serwery MCP są osiągalne tylko przez gateway.

## Reverse proxy (`proxy/`, usługa `proxy`, profil `m2`)

| Ścieżka | Cel | Uwagi |
| --- | --- | --- |
| `/` | `portal-web:8080` | statyczny serwer SPA (`portal-web/nginx.conf`): fallback na `index.html`, nonce CSP z `$request_id` |
| `/api`, `/api/` | `portal-bff:8080` | callback OIDC BFF: `http://localhost:18740/api/v1/auth/callback` (zarejestrowany w Keycloaku) |
| `/s/`, `/v/`, `/.well-known/oauth-protected-resource*` | `mcp-gateway:8080` | tylko publiczny listener; `Cookie` usuwany, `Set-Cookie` ukrywany, `nosniff` i CSP `default-src 'none'; sandbox` z `always`, błędy proxy jako JSON |
| `/.well-known/` (reszta), `/admin/v1/` | 404 | JWKS i C5 gateway'a są na osobnym listenerze mTLS (8443), do którego proxy nie ma trasy ani certyfikatu |

Ścieżki przechodzą dalej bez zmian, więc "normalizacja" to odrzucanie: zakodowane kropki, ukośniki, backslash,
`%25`, `%00`, segmenty `.`/`..` i `//` w części ścieżki dają 404 (wszystkie trasy). `X-Request-Id` nie jest
tworzony ani zmieniany. `X-Forwarded-For/Host/Proto` ustawia proxy (wartości klienta są zastępowane),
`Forwarded` i `X-Real-IP` klienta są usuwane. Upstreamy są rozwiązywane przy każdym żądaniu: restart gateway'a
albo BFF nie wymaga restartu proxy. Bez TLS (lokalnie `localhost` jest zaufanym originem); certyfikat dla proxy
nie jest wystawiany.

`make proxy-test` (`scripts/proxy-test.sh`, curl): 106 sprawdzeń na zastępczych upstreamach w osobnej sieci
Docker, każda reguła z przypadkiem dodatnim i ujemnym; nie dotyka działającego stosu.

## Mocki systemów (`mocks/systems/`, Python, bez zależności)

Jeden obraz `python:3.12-alpine`, `MOCK_SYSTEM` wybiera moduł. Dane tylko dla znanych PAT (`alice-pat`,
`bob-pat`, `carol-pat`, `mallory-pat`); token z IdP i cudzy token dają 401 (brak token passthrough). Bez stanu.
`GET /__mock/health` otwarte, `GET|DELETE /__mock/journal` z Basic `admin:$MOCK_ADMIN_PASSWORD`
(`make mock-auth SYSTEM=gitlab`: kto i czym się uwierzytelnił, bez wartości tokenów).

| Mock | Host | Sieć compose | Co |
| --- | --- | --- | --- |
| GitLab | `http://localhost:18741` | `http://gitlab.internal:8080` | OAuth (authorize, token, refresh, revoke), `GET /api/v4/user`, REST dla `mcp-server-gitlab` |
| Confluence | `http://localhost:18742` | `http://confluence.internal:8080` | `GET /rest/api/user/current` (whoami), treść, wyszukiwanie CQL, tworzenie strony |
| Service Desk | `http://localhost:18743` | `http://servicedesk.internal:8080` | `/api/v1/queues/{q}/tickets`, `/tickets/{id}`, notatki; klucz serwisowy `SERVICEDESK_API_KEY` |
| OpenSearch | `http://localhost:18744` | `http://opensearch.internal:8080` | `_resolve/index`, `_search`, `_doc`, `_alias`; JWT z token exchange (`aud=opensearch`) |

Testy jednostkowe: `make mocks-test` (165). Dane demo: GitLab `team-a/app` (id 42), `team-a/infra`, `team-b/secret`
(alice bez dostępu -> 404); Confluence przestrzenie `ENG`, `HR`, `OPS`; Service Desk `IT-1..4`, `HR-*`, `FIN-*`
(w tym zgłoszenie przeniesione między kolejkami); OpenSearch `logs-team-a-*` (alice, bob), `logs-team-b-*` i
`hr-payroll` (403 dla wszystkich).

### GitLab jako dostawca OAuth

Klient `mcp-broker`, sekret `GITLAB_OAUTH_CLIENT_SECRET` (`.secrets/dev.env`, także w OpenBao pod
`secret/mcp/oauth-clients/gitlab`, polityka brokera ma tam tylko odczyt). Redirect URI: `${MCP_PORTAL_URL}/api/v1/oauth/callback`
(`http://localhost:18740/...`; dodatkowo `:18090` dla BFF na hoście). PKCE S256 i `state` są wymagane; zły klient
albo `redirect_uri` nie przekierowują (400). Kod jest jednorazowy i ważny 120 s; access token żyje
`GITLAB_MOCK_TOKEN_TTL` s (domyślnie 7200, w `.env` można dać 60 do oglądania odświeżenia i zrestartować
`gitlab-mock`); refresh z rotacją (stary access i refresh przestają działać). Stan jest w pamięci: restart mocka
unieważnia wszystkie tokeny.

`/oauth/authorize` bez dodatkowych parametrów pokazuje stronę wyboru konta (alice, bob, carol, mallory) i
"Deny". Wybranie konta innego niż użytkownik portalu daje `identity_mismatch`. Parametry dopisywane do adresu
w pasku przeglądarki (lub przez skrypt):

| Parametr | Skutek |
| --- | --- |
| `mock_user=<login>` | zatwierdza bez strony wyboru |
| `mock_action=deny` | `error=access_denied` (portal: `cancelled`) |
| `mock_scenario=wrong_state` | w callbacku inny `state` (broker/BFF: `flow_invalid`) |
| `mock_scenario=provider_error` | `error=server_error` zamiast kodu |
| `mock_scenario=token_error` | endpoint `token` odpowiada 500 dla tego kodu |
| `mock_scenario=refresh_revoked` | refresh tego grantu daje `invalid_grant` (połączenie `revoked`) |
| `mock_scenario=short_ttl` | access token żyje 30 s |

## Profil `m2` (`make images-m2`, `make up-m2`)

`make images-m2` buduje z `git archive` HEAD obrazy BFF i web (repo `mcp-portal`) oraz czterech serwerów ws-04
(`ONLY=web,gitlab` ogranicza zestaw); tagi `m2-<sha>` trafiają do `.env`. `make up-m2` dokłada do `make up-full`:
`proxy`, `portal-web`, `portal-bff`, `mcp-confluence`, `mcp-gitlab`, `mcp-servicedesk`, `mcp-opensearch`
(`--no-recreate`, działające usługi nie są ruszane). Serwery mają `MCP_<SYSTEM>_ALLOW_PLAIN_HTTP=true`
(mocki po http), `MCP_CONNECT_URL=http://localhost:18740/connections?system={system}`, własne certyfikaty i
użytkowników Redisa. Service desk: `MCP_SERVICEDESK_CREDENTIAL_MODE=service-account`, kolejki `IT`.

Czego jeszcze nie ma w tym stosie (integracja końcowa, po M2 ws-05/06/07/08): wpisy serwerów w konfiguracji
gateway'a (`MCP_SERVER_<X>_URL`), `publicBaseUrl` gateway'a i `MCP_CONNECT_URL` `mcp-jira` na adres proxy,
konfiguracja OIDC BFF dla kontenera (backchannel `http://keycloak:8080`), poświadczenie `service-account`
service desku w brokerze (klucz: `SERVICEDESK_API_KEY`), `token-exchange` OpenSearch.

## `make m2`

Szkielet scenariusza demo: mocki (whoami, brak passthrough, REST), przepływ OAuth z mockiem (symulacja brokera
i prawdziwy broker: `oauth/start` -> authorize -> `oauth/complete`, `identity_mismatch`, zły `state`, odmowa,
rozłączenie), Keycloak (callback BFF pod `/api` na adresie proxy przyjęty, obce adresy odrzucone), proxy na
działającym stosie. Kroki wymagające BFF, web i gateway'a M2 są wypisane jako SKIP z nazwą braku.
